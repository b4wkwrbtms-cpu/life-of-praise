# v24 — 편집 복구와 모바일 곡 이동

## 확인한 문제

- 저장 요청 중 추가 편집이 있어도 이전 요청이 완료되면 잠시 ‘저장됨’으로 표시됐다.
- 앱/탭이 종료되면 아직 서버에 저장하지 못한 편집은 복구할 수 없었다.
- 동시 편집의 409 오류 이후 초안을 보관하고 빠져나오는 경로가 없었다.
- 모바일 악보 집중 화면에서 다른 곡을 선택하려면 설정 화면으로 돌아가야 했다.

## 반영

- 편집 저장을 한 줄의 큐로 처리한다. 앞선 요청 뒤에 생긴 편집도 저장한 후
  ‘서버에 저장됨’으로 표시한다. 중복 저장·닫기 요청은 같은 큐를 기다린다.
- 편집 변경 시 텍스트·송폼·악보 배치와 파일 참조를 기기에 보관한다.
  사용자/교회/예배/편집 창별로 나누며 악보 이미지 원본을 중복 저장하지 않는다.
- 복구 시 사용자가 이어갈지, 해당 보관본을 버릴지, 나중에 결정할지 선택한다.
  서버 내용이 달라졌으면 새 예배 초안인 ‘복구본’으로만 보관한다.
  다른 편집 창의 보관본은 지우지 않는다. 이미 서버와 같은 보관본은 정리한다.
- 저장 실패·오프라인·동시 편집 상황을 편집 화면에 계속 표시한다. 연결이 돌아오면
  미저장 내용을 재시도한다. 기기 보관이 성공한 경우 보관 후 닫기를 제공한다.
- 저장 응답만 유실되어 다음 요청이 충돌하는 경우, 서버 초안이 전송한 내용과
  정확히 같을 때만 저장 성공을 인정한다. 다른 내용은 자동으로 덮어쓰지 않는다.
- 저장 중 되돌리기 했을 때도, 아직 처리 중인 서버 요청과 다른 현재 편집은 보존한다.
- 모바일 악보 상단의 곡 선택 메뉴에서 바로 이동한다. 각 곡의 마지막 페이지를
  페이지 ID로 기억한다. 하단 두 편집 탭은 계속 동일한 위치에 둔다.
- 복구 안내는 기존 아이보리/초록 디자인을 유지하고, 저장 경고는 작은 황갈색 안내로 표시한다.

## 검증

- 저장 큐, 저장 중 추가 편집/되돌리기, 중복 호출, 오프라인/연결 복구,
  로그인 오류, 충돌 차단, 저장 응답 유실 및 복구 보관 분리 테스트.
- 곡 이동 시 페이지 유지, 페이지 순서 변경/삭제, 고정 편집 메뉴 구조 테스트.
- 기존 악보 전체 ZIP, 송폼 렌더링, 예배 저장/공개 API 회귀 검사.
- TypeScript 및 프로덕션 빌드.

## 범위와 한계

- 기기 보관은 해당 브라우저의 저장 공간을 사용한다. 저장 공간 사용이 막혔거나
  브라우저 데이터가 지워지면 복구할 수 없으며, 보관 실패 시 화면에서 알린다.
- 오프라인 신규 접속/악보 업로드/공개를 지원하는 것은 아니다. 이미 열린 편집의
  미저장 변경을 보호한다. 복구본 생성과 서버 저장에는 연결·인도자 권한이 필요하다.
- 복구 보관 1건은 JSON 2백만 문자 이내이며, 오래됐다는 이유로 자동 삭제하지 않는다.
- 실제 iPhone/Android 터치·키보드·강제 종료 후 재실행은 직접 검증하지 못했다.
  현재 환경에서 허용된 브라우저 QA 도구가 없어 코드/기능 검증만 수행한다.
- 운영 DB 스키마와 권한 정책은 바꾸지 않는다. 운영 회원/예배 데이터도 직접 수정하지 않는다.
