# 개인·팀원 전체 악보 보기 (v25)

## 변경 이유와 이용 흐름

전체화면 합주는 공통 완성 이미지(`song.exports`)만 열고 있어 저장된 개인 연주 표시가 사라진 것처럼 보였다. 저장 데이터는 유지되어 있었다.

- 전체화면 합주와 전체 다운로드는 기본으로 로그인한 사람의 악보를 연다.
- 상단 선택에서 내 악보, 공통 송폼 악보, `파트 · 이름`으로 구분된 팀원 악보를 고른다. 같은 파트여도 사용자 ID로 별도로 조회한다.
- 내 연주 표시의 `내 표시로 전체 악보 보기`는 진행 중인 저장과 그 사이 발생한 변경까지 저장한 뒤 해당 곡부터 합주 보기를 연다.
- 팀원의 악보는 읽기 전용이다. 개인 표시 수정 API는 로그인한 작성자에게만 쓴다.
- 전체 ZIP과 지원 기기의 이미지 공유에도 현재 선택한 사람의 저장된 표시를 담는다. 선택이 바뀌면 이전 ZIP을 즉시 숨기고 생성을 취소한다.

## 저장·접근 경계

`GET /api/services/:id/score-views?version=N&user=USER_ID`는 현재 교회의 공개된 예배 버전과 활동 중인 팀원만 조회한다. user 생략은 본인, common은 개인 표시 없는 공통 악보다. 같은 교회 총관리자 접근은 기존 교회 접근 권한을 따른다.

사용자·예배·곡별로 선택한 버전 이하의 가장 최근 개인 표시를 가져온다. 최신 기록의 빈 notes는 명시적 삭제로 처리하며 이전 표시를 되살리지 않는다. 공개 예배에 없는 곡은 응답에서 제외한다. 개인 완성 이미지 파일 ID는 반환하지 않으며 파일의 기존 소유자 접근 제한도 유지한다.

화면과 다운로드는 공통 원본/송폼/구간 표시 위에 선택된 사람의 note 데이터만 합성한다. 오래된 개인 내보내기 이미지는 사용하지 않는다. 같은 공통 이미지를 두 곡이 재사용하더라도 개인 표시 합성 결과는 곡·페이지별로 구분한다.

예전 버전에서 이어진 표시는 위치 확인 안내를 보여 준다. 교체되어 현재 존재하지 않는 페이지의 메모는 다른 페이지에 임의로 그리지 않으며 안내 목록에서 내용을 보존한다. 작성자가 내 연주 표시에서 현재 페이지로 이동할 수 있다.

조회 실패는 오류와 재시도로 표시한다. 다른 사용자를 선택하는 순간 이전 사용자의 결과를 숨기며, 늦게 도착한 응답은 현재 선택을 바꾸지 않는다. API는 no-store이며 화면의 새로 불러오기 버튼으로 최신 저장 내용을 가져온다. 실시간 협업 편집은 추가하지 않았다.

## 검증

- TypeScript 검사, 프로덕션 빌드, diff 공백 검사 통과.
- `tests/score-views.mjs`: 사용자·곡·페이지 분리, 교체 페이지 보존, 버전 확인, 빈 표시와 공통 보기.
- `tests/score-view-selection.mjs`: 실제 선택 hook의 응답 순서 뒤바뀜, 즉시 사용자/교회 격리, 실패와 재시도, 해제 이후 응답 무시; 선택 메뉴의 서버 렌더링.
- `tests/score-render.mjs`: 서로 다른 드럼·보컬 메모의 실제 PNG 픽셀/위치 검증, 공통 송폼 보존, 동일 공통 이미지를 쓰는 두 곡의 ZIP 결과 분리.
- `tests/week-download.mjs`: 순서·다중 페이지·중복 제목·파일명·취소·용량 제한·오류 시 부분 성공 방지.
- `tests/api-integration.mjs`: 기본 본인 조회, 같은 파트의 다른 두 사용자, 다른 팀원의 읽기/수정 차단, 개인 파일 비노출, 버전 계승과 삭제, 미공개 악보 차단 및 기존 기능 회귀.
- `tests/church-isolation.mjs`: 총 104개 API 요청 검사. 양쪽 교회에 가입한 동일 사용자의 파트/메모 분리, 교회 간 접근 차단, 활동 중지·탈퇴 계정 조회 제외 및 기존 관리 기능 회귀.

테스트는 로컬 격리 저장소와 이미지 렌더러에서 수행했다. 운영 데이터는 변경하지 않았다. 브라우저 및 아이폰/안드로이드 실기기 터치 검증은 이 환경에서 수행하지 못했다.

기존 데이터 마이그레이션이나 권한 일괄 변경은 필요 없다. 새 조회 경로만 기존 개인 표시 데이터를 읽는다.
