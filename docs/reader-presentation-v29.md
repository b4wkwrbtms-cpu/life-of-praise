# 연속 두 장 보기와 발표 모드 (v29)

## 사용 경로

이번 주 → 전체 악보로 합주하기 → 자동 / 한 장 보기 / 두 장 나란히.
전체 악보 화면의 발표 시작 버튼으로 발표 모드에 진입한다. 넓은 화면은 자동으로 두 장을 표시하며, 화면에 실제로 남은 폭과 높이를 기준으로 판단한다. 수동 설정은 이 기기의 교회·사용자별로 기억한다.

- 찬양 순서와 각 곡의 페이지 순서대로 연결한다. 왼쪽에 곡의 마지막 장, 오른쪽에 다음 곡의 첫 장이 올 수 있다.
- 이전·다음은 현재 표시 장수만큼 이동한다. 홀수로 끝나는 마지막 장은 가운데 한 장으로 표시한다.
- 화면 맞춤은 이미지와 합성 캔버스를 모두 자르지 않고 표시한다. 너비 맞춤·150% 확대에서는 두 페이지 묶음을 함께 스크롤한다.
- 발표 모드는 설정 영역을 숨기며, 넘김·페이지 정보·발표 종료는 악보와 겹치지 않는 하단 영역에 남긴다.
- 브라우저 전체화면 요청은 클릭 시 즉시 실행한다. 지원하지 않거나 거부된 경우 앱 내부의 발표 화면을 사용한다.
- 방향키·Page Up/Down·Space·Shift+Space·Home·End 및 좌우 스와이프로 이동한다. 입력 요소의 키 조작과 핀치 확대는 방해하지 않는다.
- Esc 또는 발표 종료는 전체 악보 화면으로 돌아온다. 현재 페이지, 선택한 악보 작성자, 이전 확대 설정은 유지한다.
- 동일한 선택 작성자의 최신 개인 메모를 양쪽 페이지에 각각 합성한다. 다른 작성자 로딩 중에는 이전 작성자 악보를 표시하지 않는다. 공통 송폼을 다시 렌더링해야 하는 곡은 오래된 이미지 내보내기를 사용하지 않는다.

## 검증

- `tests/reader-presentation.mjs`: 실제 컴포넌트의 훅·이벤트 처리와 DOM 경계를 모의 실행. 곡 경계를 넘는 두 장, 홀수·빈 목록, 페이지 이동, 곡 바로 이동, 화면 크기 변경, 위치·보기 방식 유지, 양쪽 개인 메모, 작성자 전환, 오류·이미지 대체 렌더링, 키보드·터치, 발표 진입·종료, 전체화면 거부·소유권·이벤트 정리를 검증한다. CSS는 Safari/Chrome 타깃으로 컴파일한다.
- `tests/score-view-selection.mjs`: 기존 작성자·교회 분리, 늦게 도착한 응답, 실패·재시도 및 읽기 전용 선택 표시 검증.
- `tests/score-render.mjs`: 실제 캔버스의 송폼·구간·개인 메모 합성과 작성자별 이미지 분리 검증.
- TypeScript 타입 검사와 프로덕션 빌드.

검증 한계: 이번 환경에서는 브라우저 및 실제 iPad·노트북의 화면 배치, 운영체제 전체화면을 직접 실행하지 않았다. 자동화 검증은 DOM 경계를 모의 처리한 기능 테스트와 렌더러·스타일 컴파일 검증이다.

서버 데이터, 권한, 알림, 배포 환경 변수에는 변경이 없다.
