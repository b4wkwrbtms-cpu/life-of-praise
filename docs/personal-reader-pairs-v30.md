# 개인별 두 장 보기 설정 (v30)

## 사용 경로

- 이번 주 곡 → 내 악보 → 두 장 선택. 편집 중인 개인 메모를 먼저 저장한 뒤, 현재 페이지가 선택된 상태로 설정을 연다.
- 전체 악보 → 함께 볼 두 장 선택. 같은 곡 또는 다른 곡의 페이지 두 장을 선택해 저장한다.
- 묶음 추가로 여러 묶음을 만들고, 각 묶음의 좌우를 바꾸거나 해제할 수 있다. 묶지 않은 페이지는 한 장씩 남는다.
- 저장하고 보기는 내 두 장 묶음 모드로 전환한다. 선택한 배치는 발표 모드에서도 유지된다. 기존 자동·한 장·연속 두 장 보기도 계속 사용할 수 있다.
- 다른 기기에서는 같은 계정으로 로그인하고, 전체 악보의 보기 선택에서 내 두 장 묶음을 고르면 저장한 설정을 불러온다.

## 저장 및 경계

`reader_pairs`는 교회·사용자·예배·공개 버전별 설정과 수정 번호를 보관한다. 읽기와 쓰기는 로그인한 본인에게만 허용한다. 총관리자도 다른 사용자의 설정을 조회·변경하는 경로를 제공하지 않는다.

페이지는 곡 ID와 페이지 ID를 함께 사용해 구분한다. 같은 파일을 가져온 다른 곡도 각각 선택할 수 있다. 한 페이지는 하나의 묶음에만 들어간다. 서로 떨어진 페이지를 묶으면 그중 콘티에서 먼저 나오는 페이지 위치에 묶음을 배치하며, 묶음 안의 좌우는 사용자가 선택한 순서를 따른다. 다른 페이지를 누락하거나 중복하지 않는다.

새 버전은 이전 개인 설정을 이어받는다. 교체·삭제된 페이지가 있는 묶음만 제외하고 설정 화면에 안내한다. 명시적으로 빈 설정을 저장하면 예전 묶음을 다시 자동 복원하지 않는다. 동시에 저장할 경우 수정 번호로 충돌을 감지하며, 네트워크·충돌 오류에서는 편집 중인 선택을 유지한다. 영구 삭제한 예배의 설정은 외래 키로 정리한다.

공통 곡 순서·송폼·파일·개인 메모 데이터에는 쓰지 않는다. 팀원의 악보를 선택해 읽을 때도 보기 배치는 접속자 자신의 설정을 사용한다.

## 검증

- `reader-pairs.mjs`: 임의 두 페이지, 좌우 순서, 복사된 파일의 곡별 구분, 중복·교체 페이지 처리, 전체 페이지 누락 방지, 설정 훅의 계정·교회 전환과 늦은 응답 차단, 중복 저장 방지, 오류 복구, 선택·해제·검색·취소 동작 및 마크업 검증.
- `reader-presentation.mjs`: 기존 발표 모드 검증에 직접 선택한 묶음의 표시·넘기기·발표 유지·설정 화면 연결 추가. 두 페이지에 개인 메모를 별도로 합성하는 경로 유지.
- `reader-pairs-api.mjs`: 빌드된 Worker와 로컬 D1/R2에서 50개 API 확인. 저장 재조회, 사용자·교회 경계, 입력 검증, 동시 저장, 공통 자료·개인 메모 보존, 버전 계승, 악보 교체, 권한 회수, 삭제 정리.
- 기존 모바일 작업 영역 테스트, TypeScript 검사, 프로덕션 빌드, Safari/Chrome 대상 스타일 컴파일.

실제 브라우저 화면 배치와 패드·노트북 전체화면은 직접 실행하지 않았다. UI 검증은 컴포넌트 이벤트·훅을 모의 실행하고, 서버는 로컬 Worker에서 검증했다.
