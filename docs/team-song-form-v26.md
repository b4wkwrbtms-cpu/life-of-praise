# 찬양팀 송폼 수정 권한 (v26)

## 동작

모든 활동 중인 교회 팀원이 공개된 곡의 **송폼 수정**을 열 수 있다. 악보 화면에서 개인 표시 저장을 마친 뒤 송폼 전용 편집기로 이동한다. 현재 공개된 최신 버전을 읽으며, 송폼 순서·반복·페이지별 위치·크기·구간 표시를 편집한다. `팀에 반영`을 누르면 공통 악보의 새 버전으로 반영되고 작성자·세션과 변경 내용이 기록된다. 개인별 송폼 사본이 아닌 팀 공통 송폼을 수정하는 기능이다.

곡 제목·키·BPM·곡 추가/삭제·순서 변경·원본 악보 업로드/교체·예배 내용·팀원 관리 권한은 확대하지 않았다. 곡 관리와 원본 악보 관리는 기존 인도자 권한을 유지한다. 다른 사람의 개인 메모도 수정할 수 없다.

휴대폰 편집 화면은 송폼 순서와 악보 편집을 전환하는 메뉴를 스크롤 영역 밖에 둔다. 되돌리기/다시 실행, 페이지 이동, 수정 취소 확인, 저장 실패 시 입력 유지, 짧아진 화면 높이 대응을 포함한다. 송폼 입력 도구는 인도자 편집기와 공유하며 기존 Cx2, Bridge x 2와 구간 ID 보존 방식을 사용한다.

## 서버 저장 범위와 충돌

`/api/services/:serviceId/songs/:songId/form`의 GET은 현재 교회의 공개 악보만 반환하고 미공개 초안은 반환하지 않는다. PATCH는 form/layout/markers/pageLayouts만 받는다. 페이지 목록은 기존 페이지 집합과 일치해야 하며 페이지 ID, 원본, 크기, 순서를 교체할 수 없다. 다른 필드 추가 및 곡 생성 요청을 거부한다.

기존 개인 표시 행은 수정하지 않는다. 개인 메모는 새 버전에서도 기존 정책대로 이어서 보이고 위치/구간 검토가 필요한 경우 안내한다. 이전 공개 버전도 그대로 보존한다.

공개 데이터와 인도자의 미공개 초안 중 수정 대상 곡의 송폼/페이지 배치가 같으면 해당 부분만 양쪽에 반영한다. 인도자의 미공개 제목·공지·새 곡 등은 미공개 상태로 보존한다. 같은 곡의 송폼이나 페이지 목록이 이미 다른 경우에는 충돌을 알리고 덮어쓰지 않는다.

예배 revision과 공개 version을 함께 검증하고 D1 batch로 새 버전 삽입과 현재 상태 갱신을 처리한다. 동시에 저장하면 한 요청만 반영한다. 인도자의 오래된 편집 창에서도 기존 revision 검사가 팀원 수정 덮어쓰기를 막는다.

## 이미지와 전체 다운로드

팀원에게 공통 파일 업로드 권한을 주지 않는다. 수정한 곡은 서버가 `renderOnRead: true`, `exports: []`로 기록하고, 원본 악보에 최신 송폼을 합성해 표시·저장한다. 이를 통해 예전 송폼이 포함된 완성 이미지를 다시 보여주는 것을 막는다. 전체 ZIP도 공통/개인/다른 팀원 선택에 맞춰 새 이미지를 생성한다. export ID가 없는 페이지는 곡·페이지별로 구분해 캐시한다. 기존 이미지 생성 및 악보 크기 제한을 유지한다.

## 검증

- 프로덕션 빌드, TypeScript, diff 공백 검사.
- `tests/song-form-permissions.mjs`: 57개 API 검사. 팀원 수정, 허용 필드 제한, 원본 파일/곡 관리 제한, 미공개 내용 분리·보존, 기록과 개인 메모 보존, 중복 저장/동시 저장/오래된 인도자 저장 충돌, 비활성·삭제 접근 차단.
- `tests/church-isolation.mjs`: 108개 교회 API 검사. 송폼 조회/수정의 다른 교회 접근 차단을 추가했다.
- `tests/song-form-ui.mjs`: 구간 ID와 페이지 원본·제목 등 보존, 기존 공개 객체 불변, 반복 송폼과 순서 버튼 렌더링.
- `tests/week-download.mjs`: 새 송폼의 동적 페이지 다운로드, 빈 export ID 캐시 충돌 방지 및 기존 ZIP 검증.
- `tests/score-render.mjs`, `tests/api-integration.mjs`: 기존 악보·메모 합성 및 주요 기능 회귀 검사.

모든 데이터 변경 검사는 로컬 테스트 저장소에서 수행했다. 운영 자료 및 팀원 역할 행을 직접 변경하지 않았다. DB 마이그레이션은 필요 없다. 실제 브라우저 및 iOS/Android 실기기 터치 검증은 이 환경에서 수행하지 못했다.
